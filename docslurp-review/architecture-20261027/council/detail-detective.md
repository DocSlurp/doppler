## Contract and edge-case assessment

- **Shared C++ facts and geometry:** `utils/pdftotext.cc:250-291` centralizes logical text, metadata selection and line union. All three structured writers consume the projection, while XML escaping, TSV sanitation, numeric precision and framing remain format-specific. Initializing the union from the first word fixes zero-as-sentinel minima and also handles entirely negative bounds. `getLogicalText(uMap)` remains the source of text; no extra RTL reversal was introduced. Metadata is still optional and the font-name selection matches the old first-character rule. Empty lines now have zero bounds, a sensible diagnostic difference rather than a content regression.
- **Index spaces and overlapping regions:** `page_layout.rs:66-84` and `:95-139` retain page-global line IDs throughout detection and membership replacement. Table placements carry their payload rather than an index into a separate table vector. Membership is a fresh collection for each region; the same narrow-gutter line may belong to a left table and right prose without stale flags leaking between them. HashSet iteration does not affect output order: it is used only for membership, while retained placements and detected tables preserve their order. Ruled tables, gutter tables and remaining lines retain the prior stable tie ordering. Ruled detector disjointness and gutter membership generation remain unchanged.
- **Original neighbors and titles:** `page_layout.rs:146-185` examines the next original FlowItem before it is absorbed, and updates `previous_table` according to the original item stream. A minor heading before an absorbed title therefore does not become a caption merely because the title disappears. The title is assigned to the table header before rendering. Paragraph/list/heading precedence and title eligibility match the baseline. The adjacent-table fixture specifically exercises this trap.
- **Depth and atomic fallback:** `lib.rs:285` now requests a completed PageLayout. The old parallel table/geometry vectors and caller-managed consumed/marked reset protocol are removed, not merely hidden unchanged under a renamed function. `PageLayout::within` finishes region assignment, grouping and ownership before `markdown` serializes it. If a later region exhausts the budget, the local partial blocks are discarded; the caller emits the existing full-page fallback. Document-level furniture/body statistics and shared budget lifetime appropriately remain outside the page module.
- **Caps and completeness:** `poppler/TextOutputDev.cc:2949-2959` decrements the remaining document allowance before testing whether the page is full, without underflow at zero. Exactly 20,000 retained rules is complete until another eligible candidate is rejected. The 200,000-candidate limit includes attempts rejected by full pages. Clipping/eligibility still precedes acceptance at `:5947`; an empty or clipped-only page after exhaustion is not falsely marked truncated. Page clearing resets completeness, while the document allowance survives page changes as before.
- **Report propagation:** `model.rs:568-587` preserves true/false/unknown producer state and records truncated pages even with no retained rules or no closing page tag. `lib.rs:207-231` changes zero-based library indices to one-based JSON consistently with degradation. Upstream truncation does not force layout degradation, and early layout fallback cannot hide the already-collected marker.

Matching failure status is not proof of identical error diagnostics, and no claim of that is needed here.

The script also checks separate layout degradation. It deliberately disables table inference for these high-rule-count cases; actual ruled-table output is covered separately by the Rust fixture. Thus the pipeline proves propagation/accounting, not high-quality table recovery from truncated evidence.

## Considered and rejected; residual risks

Rejected suspected regressions from region overlap, table index remapping, unstable hash iteration, caption changes after title removal, exact-limit off-by-one behavior and loss of truncation during fallback: code paths and targeted existing tests directly address them. I also reject treating harmless numeric/formatting changes or a roughly one-percent bbox CPU increase as blockers.

Residual risks are inherited layout heuristics on unusual PDFs, imperfect tables when producer evidence is truncated, the pending authored-reference quality result and limited timing generalizability. The real pipeline check is currently an explicitly invoked script; adding it to a routine check that builds both programs would be a useful optional integration safeguard. None of these establishes a present behavior bug. The coordinator should reconcile the completed quality artifact and its denominator before presenting the final evidence set as complete.
